# Агент с инструментами: фиксированный конвейер, ReAct и план

Цель работы — понять, что на одном замороженном наборе задач даёт фиксированный конвейер, цикл ReAct и план с последующим исполнением, если все три режима вызывают одни и те же инструменты и одну и ту же модель. Нужен был срез, на котором видны успех, число токенов и задержка, без подгонки промптов после просмотра ответов.

Сделано следующее. Мир компании, 44 задачи и лимиты шагов зафиксированы до прогона. На них посчитаны свой конвейер, свой ReAct, план-и-исполнение и тот же ReAct, собранный как граф LangGraph. Сервер — уже запущенный vLLM с `Qwen/Qwen3.8-27B-FP8`, имя в API `Qwen3-VL`. Поле `tools` этот процесс не принимает, поэтому вызов инструмента записан текстом в ответе модели. Процесс не перезапускался.

Получилось, что конвейер на этом срезе заметно дешевле и надёжен на арифметике, поиске карточки, развилке и починке ошибки инструмента: 35 из 44 задач, 367.1 токена и 1.245 с в среднем. Четыре задачи про политику и все четыре открытые задачи он не решает. ReAct решает все 44, включая открытые, и тратит 3305.9 токена и 1.711 с. План повторяет успех ReAct и стоит дороже: 4145.7 токена и 3.520 с. Граф LangGraph совпадает с собственным ReAct по успеху и отличается на десятки токенов. Числа сняты с `reports/dev.json`. Команда `python -m lab.eval --split check` сверяет таблицу с этим файлом до напечатанных знаков.

| система | success | mean_total_tokens | mean_latency_s | mean_model_calls | mean_tool_calls |
| --- | --- | --- | --- | --- | --- |
| workflow | 0.7955 | 367.1 | 1.245 | 1.66 | 1.45 |
| react | 1.0000 | 3305.9 | 1.711 | 2.57 | 1.82 |
| plan | 1.0000 | 4145.7 | 3.520 | 3.77 | 1.84 |
| react_lg | 1.0000 | 3270.9 | 1.777 | 2.55 | 1.80 |

Успех — доля задач, где извлечённый ответ совпал с золотом. Токены — сумма prompt и completion по ответам vLLM, среднее по 44 задачам. Своего тарифа нет: модель крутится на своей карте, поэтому стоимость здесь — токены, а не деньги. Задержка — стенные часы одного запроса за раз, от первого вызова модели до готового ответа. Медиана задержки: workflow 0.894 с, react 1.325 с, plan 2.405 с, react_lg 1.473 с. При чётном числе задач медиана — среднее двух центральных значений.

По семьям успех workflow равен 1 на calc, lookup, branch и recover (8, 8, 4 и 6 задач), 0.8750 на compose (7 из 8), 0.3333 на policy (2 из 6) и 0 на open (0 из 4). У react, plan и react_lg успех 1.0000 на каждой семье.

## Постановка

Мир лежит в `lab/world.py` и после сборки не менялся. Двенадцать сотрудников, пять отделов, три текста политики. Курсы: USD 93, EUR 100, CNY 13 рублей, перевод через рубли, дробная часть отбрасывается целочисленным делением. Дата среза `2026-10-11`. Основа фамилии складывает конечную «а», поэтому «Иванов» находит и «Иванова». Белов Кирилл числится в продажах, город у него Москва, а город отдела продажи — Новосибирск, поэтому в сумму `o01` он не входит.

Золото считается функциями мира, а не записывается руками. Семьи: calc 8, lookup 8, compose 8, policy 6, branch 4, recover 6, open 4. Идентификаторы и тексты — `lab/tasks.py`, sha256 `f1eb0d94fcfd264a604b34595f07e1cc3f5cc041ff1275ead8a1d806c3626401`.

Инструментов семь: `lookup_employee`, `lookup_department`, `list_employees`, `calculate`, `convert_money`, `years_between`, `search_policy`. `calculate` считает только AST из чисел и `+ - * / // %`; `/` и `//` — целочисленное деление, имена запрещены, деление на ноль и кривой синтаксис возвращают ошибку. Курсов в описании `convert_money` нет: модель узнаёт их только из ответа инструмента. Неизвестная валюта — ошибка `unknown_currency`. Вызов сначала проверяется по JSON Schema; исключение инструмента становится `{ok: false, error, detail}`, а не падением цикла.

Ответ берётся с последней метки `ANSWER:` или `ОТВЕТ:`. Для целого золота допускаются пробелы и хвостовая единица измерения. Строка должна совпасть целиком после casefold и замены `ё` на `е`. Предложение, внутри которого золотая строка просто встречается, зачётом не считается.

Семья задачи известна только конвейеру. ReAct и план видят вопрос и схемы инструментов.

## Протокол

Температура 0, seed 42. Лимиты ReAct и конвейера записаны до прогона 44 задач: ReAct не больше 8 шагов модели, конвейер не больше 5 вызовов модели. План на том прогоне тоже был ограничен 8 вызовами модели, 4 шагами и 2 вызовами внутри шага; эти числа лежат в `reports/dev.json`. Сейчас потолок плана — 20 вызовов модели и 6 шагов, внутри шага по-прежнему 2. Промпт ReAct, sha256 `aae5234735339935f256a5784a05cd9d9be1d6bc221e32d32d6f2da6dca72cec`, после прогона не менялся. Промахи среза из 44 ниже оставлены как есть.

Сервер — `http://10.109.50.250:1212/v1`. `GET /v1/models` возвращает id `Qwen3-VL`, корень весов `Qwen/Qwen3.8-27B-FP8`, `max_model_len` 32768. Процесс поднят как OpenAI-совместимый vLLM с `--enable-prefix-caching`, `--reasoning-parser qwen3` и `enable_thinking: false`. Клиент повторяет `enable_thinking: false`, если в имени модели есть `qwen3`. Пустой `content` при строковом `reasoning` берётся из `reasoning`.

Поле `tools` этот процесс отвергает: выбор `auto` требует `--enable-auto-tool-choice` и `--tool-call-parser`, которых в команде запуска нет. Общий процесс не перезапускался. Вызов пишется блоком

```
<tool_call>
{"name": "calculate", "arguments": {"expression": "1+1"}}
</tool_call>
```

Схемы вставлены в системный промпт. Наблюдение возвращается следующим сообщением пользователя с заголовком `Наблюдения:`. Лимит шагов отдаёт пустой ответ и `stop=step_limit`. Ошибка инструмента остаётся в наблюдении, и следующий шаг модели может поправить аргументы.

Запросы шли по одному. Кэш префикса на сервере был включён, поэтому повтор длинного системного промпта почти не раздувает задержку: у ReAct среднее completion — 61.0 токена при среднем prompt 3244.8.

## Методы

**workflow.** Конвейер выбирает слот по семье. Calc просит JSON с выражением и один раз чинит его. Lookup просит сущность, имя и поле. Convert просит сумму и две валюты. Compose сначала ищет только имена, уже написанные в вопросе, потом выражение, `if` или `convert`. Policy сначала ищет подстроку в текстах политики, затем занимает тот же слот, что и вторая стадия compose. Branch делает lookups и развилку с константой или переводом валюты. Пустой поиск политики чинится один раз. Recover внутри себя смотрит на слова вопроса: «переведи» идёт в convert, «посчитай» — в calc, остальное — в lookup; чинилка может вернуть готовый `{"answer": ...}`. Open — один JSON с именем инструмента и аргументами, без каталога инструментов и без повтора, затем синтез ответа. Повтор имени `var` затирает предыдущую карточку в области видимости.

**react.** Один цикл. Системный промпт требует брать числа и имена из инструментов, при ошибке читать `error` и `detail` и звать инструмент снова, а в конце писать строку `ANSWER:`. Шагов модели не больше восьми.

**plan.** Первый вызов в JSON-режиме возвращает до шести шагов `{tool, goal}`. Один невалидный JSON чинится. Каждый шаг исполняется тем же циклом, что ReAct, но не дольше двух вызовов модели. Если шаг получил ошибку инструмента и ответа ещё нет, план пересобирается один раз. Если ответа всё ещё нет и вызовы модели ещё остались, отдельный вызов собирает его из наблюдений. Всего не больше 20 вызовов модели. На срезе из 44 задач этот потолок был 8 вызовов и 4 шага.

**react_lg.** Тот же системный промпт, тот же текстовый блок и тот же потолок в 8 шагов. Цикл собран как `StateGraph` LangGraph 1.2.7: узел модели, узел инструментов, условное ребро. Граф компилируется с `MemorySaver`: после каждого узла состояние пишется в чекпоинт, ключ потока — `thread_id`. Один saver держит все вопросы прогона. `interrupt_before=["tools"]` останавливает граф перед инструментом, `invoke(None)` продолжает тот же поток. `create_react_agent` сюда не ставился: в 1.2.7 он переехал в `langchain.agents.create_agent` и отправляет поле `tools`, которое этот vLLM отвергает. Расхождение с собственным циклом на срезе из 44 — форма графа и то, как модель упаковала одно выражение.

## Что из этого следует

На этом срезе фиксированный конвейер выигрывает по токенам и времени там, где слот уже знает, какой инструмент звать. 367.1 против 3305.9 токена — это в основном системный промпт: у конвейера среднее prompt 318.8, у ReAct 3244.8, completion 48.3 против 61.0. Задержка при этом вырастает с 1.245 с до 1.711 с, а не в те же девять раз: префикс кэшируется, а новых токенов мало.

Плата конвейера — слоты, которые не покрывают вопрос. Open не знает имён инструментов и на всех четырёх задачах зовёт выдуманное имя. Policy на четырёх из шести задач либо ищет политику по имени сотрудника, либо кладёт ветвление не в то поле JSON. Compose ломается на одной задаче из восьми, где три карточки записаны в одну переменную.

ReAct закрывает и эти девять задач. Семь ошибок инструментов у него приходятся на `l03` (две) и `r02`–`r06` (по одной), и все шесть задач всё равно зачтены: ошибка остаётся в наблюдении, следующий шаг её читает. План даёт тот же успех при 3.77 вызовах модели против 2.57 и при 139.6 completion-токенах против 61.0. Четыре его ошибки инструментов — `r02`–`r05`, они тоже не роняют ответ. Дополнительная цена плана на этом срезе — отдельный вызов планировщика и более длинный ответ, а не потеря задач.

`react_lg` повторяет успех и почти повторяет счётчики: 3270.9 токена против 3305.9 и 1.777 с против 1.711 с. Число вызовов разошлось на одной задаче, `a04`. Свой ReAct посчитал `280000*12` и `9100000-3360000` двумя вызовами `calculate` (5 вызовов модели, 4 инструмента). Граф записал `9100000 - 280000*12` одним вызовом (4 и 3). Золото в обоих случаях 5740000. На остальных 43 задачах числа вызовов совпали, включая две ошибки `ambiguous` на `l03` и открытую `o01`.

## Разбор промахов конвейера

Девять незачётов workflow. У react, plan и react_lg на этих идентификаторах ответ совпал с золотом. Полные трассы — в `reports/dev.json`, список задач, где хоть одна система ошиблась, — `reports/failures.jsonl`.

`a08`. «Чему равна сумма месячных зарплат Ивановой Анны, Петрова Игоря и Новиковой Дарьи?» Золото 580000 = 180000 + 250000 + 150000. Модель запросила все три карточки и всем трём дала `var` равный `emp`. В области видимости осталась последняя карточка, Новикова Дарья. Второе сообщение вернуло выражение `emp.salary`, инструмент посчитал 150000. Ошибки инструмента нет: сломалась подстановка, а не арифметика.

`p01`. «Сколько дней составляет базовый отпуск без надбавки за стаж?» Золото 28. Ключ «базовый отпуск» нашёл текст отпуска. В слот выражения модель положила объект `if` про `emp.start_year` и 2018 год. Починка повторила тот же JSON. Ответ пустой, `stop=error`. Сотрудника в вопросе нет, базовая ставка написана в найденном тексте.

`p02`. «Сколько дней отпуска положено Орлову Денису по политике компании?» Золото 31: год выхода 2018, политика даёт 31 день тем, кто вышел в 2018 или раньше. Первый ключ «Орлов Денис отпуск», второй «Орлов Денис». Оба поиска вернули пустой список. До выражения конвейер не дошёл.

`p05`. «Какой процент годовой премии действует в отделе «продажи»?» Золото 15. Ключ «продажи» нашёл текст премии. Выражение оказалось тернарным оператором над `emp.department` и `emp.salary` при пустой области видимости. Подстановка пути не вызвала `calculate`. Починка тоже не прошла схему. Ответ пустой. Нужное число лежит в уже найденном тексте политики.

`p06`. «Чему равна годовая премия Белова Кирилла?» Золото 243000 = 135000 × 12 × 15 / 100. Ключи «Белов Кирилл годовая премия» и «Белов Кирилл премия» в текстах политики не встречаются. Поиск оба раза пустой, до зарплаты и процента конвейер не дошёл. `p03` и `p04`, суточные за 4 дня в Казани и за 10 дней в Москве, этим слотом решены.

`o01`–`o04`. Золото 370000, 2400, 63000 и 97849. Промпт open просит ровно один инструмент и не перечисляет имена. Модель вызвала `ask_user`, `get_employee_card`, `get_employee_data` и `find_employee`. Каждый ответ — `unknown_tool`. Повтора нет. Синтез на пустом наблюдении написал `ANSWER: 0`.

ReAct на `o01` зачтен без ошибок инструментов: карточка отдела продажи, список сотрудников, затем `140000+230000`. В сумму попали Кузнецов Илья и Волкова Елена, оба в Новосибирске, как и город отдела. Белов Кирилл в Москве в сумму не вошёл.

Ошибки, которые цикл починил, в таблицу промахов не входят, но показывают, зачем наблюдение с `error`. На `l03`, «Кто руководитель Смирнова Павла?», ReAct сначала передал «Смирнова Павел»: основа совпала и у Смирнова Павла, и у Смирновой Ольги. Второй вызов с отделом «разработка» остался на той же форме и снова получил `ambiguous`. Третий вызов, «Смирнов Павел» и отдел «разработка», вернул карточку, ответ «Орлов Денис». Конвейер на этой задаче сразу запросил именительный падеж и обошёлся одним вызовом. На `r02` и конвейер, и ReAct получили `ambiguous` по фамилии Смирнов и взяли 190000 из списка кандидатов — зарплату Смирновой Ольги, — не делая второго удачного поиска. `r03` посчитал `10 / 0`, прочитал `division_by_zero` и ответил 0. `r04` на неизвестной валюте ответил −1, `r05` на отсутствующего человека ответил «нет», `r06` после отвергнутого `180000 +` посчитал `180000 + 20000`.

## Длинные цепочки

Срез из 44 задач почти не различает план и ReAct: оба закрывают всё. Отдельные шесть вопросов в `lab/long_tasks.py` длиннее. Каждый требует несколько зависимых инструментов: премия двух людей и перевод разницы, премия в долларах, бюджет отдела руководителя руководителя, годовая зарплата при неоднозначной фамилии и перевод, разница суточных по стажу, зарплата руководителя отдела в евро. Золото снова считается из мира. Семья `chain` идёт в слот compose: два этапа и одно выражение, `if` или `convert`. В основные 44 эти вопросы не входят. Первый прогон шёл при потолке плана в 8 вызовов: план закрыл 3 из 6, `d01` умер на лимите уже после верных 63000 рублей. Ниже — повтор при 20 вызовах и 6 шагах. Отчёт — `reports/long.json`.

ReAct снова закрыл все шесть за 4.83 вызова модели и 5.00 инструментов. Граф повторил ответы и числа вызовов. Чекпоинтов на вопрос от 9 до 13, потоки `q1`–`q6`. Токены 7214.2 против 7202.2 у своего цикла: на `d04` граф потратил на 72 токена больше.

План закрыл четыре задачи, включая `d01`, который раньше кончался на восьмом вызове. Средняя задержка 10.278 с, инструментов 5.17 вместо 10.83 в прогоне с потолком 8: пачки из десятков `calculate` в этот раз не было. Два промаха — уже не пустой ответ на лимите. На `d05` план получил стаж 9 и 2 года и ставки 1300 и 1200, но не применил правило «дольше 7 дней — умножить на 9 и разделить на 10». Ответ 9300 = 1300×9 − 1200×2, золото 8130. На `d06` карточка отдела поддержки сразу назвала руководителя, Орлова Дениса. Дальше план искал его с отделом «поддержка», хотя он числится в разработке, четыре раза получил ошибку и ответил 0. Вызовов было 9 из 20, бюджет ещё оставался.

Конвейер снова не закрыл ни одного. На `d01` оба процента взяты как 10, курс не вызывался, ответ −18000 вместо 677 долларов. На `d02` посчитана годовая зарплата 3360000, не премия. На `d05` ставка суточных заменена на 1000, ответ 7000 вместо 8130. На `d06` слот умеет вернуть 2800, если второй этап зовёт `convert` по зарплате руководителя; в прогоне второй поиск не прошёл, и выражение стало `0`.

## Воспроизведение

Из корня каталога `agents`.

```bash
python -m lab.eval --split dev
python -m lab.eval --split long
python -m lab.eval --split check
pytest -q
```

`make eval`, `make long`, `make check` и `make test` вызывают те же команды. Полный прогон и срез `long` ходят на `http://10.109.50.250:1212/v1` и в CI не входят: на push и pull request запускается только pytest. Для строки `react_lg` локально нужен `langgraph==1.2.7` из `requirements-eval.txt`. Пересчёт таблицы чужого отчёта сеть не требует. Чекпоинт и длинный скриптованный диалог проверяются в pytest без сервера.

| файл | роль |
| --- | --- |
| `lab/world.py` | сотрудники, отделы, политики, курсы, золотые функции |
| `lab/tasks.py` | 44 задачи |
| `lab/long_tasks.py` | 6 длинных цепочек, отдельно от среза 44 |
| `lab/tools.py` | семь инструментов и исполнение |
